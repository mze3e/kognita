## [Unreleased]

### Fixed

- Evidence truncation is now detected: `verify_export` checks the export's advertised `event_count` and `head_hash` against what it actually verified, and `verify_chain` treats a missing or unreadable head checkpoint as a chain break (not a pass) whenever events exist.
- #5: Serialize quota recheck and reservation in the decision transaction.
- #6: Lock parent run capacity before checking and reserving child budgets.
- #27: Serialize daily anomaly row creation and counter updates across workers.
- 0.5 DoD item 4 (concurrency): Enforce atomic per-minute and daily quota admission.
- #20: Require non-blank, stripped approval signers and distinct requester, marker, and confirmer identities.
- #21: Escalate checks with blank citations using CITATION-REQUIRED, preserving denials.
- #31: Require approval packet text fields and list members to contain non-blank text.
- Framework bindings carry workload credentials and delegation IDs through model and tool authorization; missing tool credentials fail closed.
- Extracted private model transport to keep the shared adapter binding within 200 lines.

## [0.5.0] - 2026-10-19

0.5 "Agents, Authority and Fleets". This is an alpha release. Not every 0.5 definition-of-done item is met, and an independent four-way review found open defects. Both are listed below under "Known open items". Read them before you rely on 0.5 controls.

### Known open items

0.5 definition-of-done items still open (partial):

- **1. Full agent identity.** Some identity fields are still optional, and deployment date and model used are not recorded fields. Review-date expiry and changed-deployment denial are not yet shown end to end through both gateways.
- **4. Blast-radius limits.** There is no daily transaction counter and no allowed-products limit. Quota admission is not atomic, so concurrent calls can exceed a per-minute or daily limit.
- **14. Automatic containment.** The human alert is an evidence event only, with no delivery. An anomaly does not cancel a backend call that is already running.
- **17. Adversarial suite.** The suite runs through a test harness, not end to end through the gateway and MCP proxy with a shipped pack.
- **19. Automatic step-down.** The alert is an evidence event only. Step-down is demonstrated through snapshot loading, not through a gateway or MCP request.
- **20. Provider credential detection.** Only declared metadata is scanned. An undeclared provider credential held by an agent is not detected.
- **21. In-flight cancellation.** The default transport has no cancellation hook. A timed-out or killed call's result is withheld and evidenced, but the backend call keeps running.

Known open review findings (fixes are planned for 0.5.1):

- A run's taint and binding can be shed by omitting or rotating `run_id` on the MCP proxy.
- The agent-to-agent delegation budget check is not atomic.
- The framework adapters (hermes-agent, openai-agents, langgraph, pydantic-ai) cannot pass an agent credential or a delegation id, so registered-agent calls through them are denied.
- Gateway model calls do not apply live-run interventions (pause, override, restrict, recover), the tool isolation checks (public-content lane, external authority, step-up, injection), or a human-approval continuation.
- `broker.ask` skips run isolation and the field allow-list.
- An envelope whose `subjects` and `subject_id` disagree is authorised on one and executed on the other.
- Evidence export verification does not detect truncation, and `verify_chain` skips the head check when the head row is missing.
- After a human approval the envelope hash changes, so the grant is not found, and a rejected hold does not release its quota.
- Approved system triggers are always denied on the gateway and MCP proxy (a product decision is pending).
- Proposal-then-apply is not implemented, and the response review-queue screener is not called from any response path.
- Replay drops child delegations and the assurance level for 0.5 decisions.
- The first two-signature signer may be blank, and policy citations may be empty.
- Smaller items: `decide()` without a use-case register, anomaly day buckets and their concurrent update, workload credentials surviving retirement, token and cost caps applied one call late, approval packet text validation, and stale cached agent rows across sessions.

### Changed

- Add tool reversibility and compensation, stronger irreversible-action approval, bounded MCP execution and cancellation evidence, reverse recovery, adversarial conformance checks and a published threat model.

- Complete delegated-run isolation, inherited restrictions, bounded authority reads and historical lineage; verify fleet quotas, authenticated MCP agent messages and restrictive sandbox output with S6b regression tests.

- Add bounded agent delegation, reserved child budgets, live authority lineage checks, run isolation, external-agent taint, authority reconstruction CLI, and evidenced sandbox constraints for execution decisions.

- Add bounded per-agent behavioral baselines, automatic anomaly quarantine, credential revocation, tool admission stops, incident evidence, and owner alerts.

- Isolate external and client data across runs and approval continuations, reject conflicting agent duties, evidence injection alerts, and require transaction-bound step-up evidence for high-risk tool calls.

- Enforce per-agent blast-radius and rolling rate limits independently of run budgets, with bounded indexed usage reads and checks at approval release.
- Minimize tool results by purpose-specific field paths and evidence each projection; support event-bound delegation windows.


- Add task-bound delegated authority, dual human entitlement checks, approval thresholds, and evidenced capability grant lifecycle.

- Add per-agent hashed workload credentials with evidenced issue and revocation, gateway and MCP authentication, deployment mode validation, and provider-key review findings.


### Fixed

- Security: an MCP delegation scoped to one client no longer authorises a tool call whose arguments (`client`, `client_id`, `clientId`, or a matching `allowed_data` dimension) name a different or conflicting client; `S3-DELEGATION` now fails closed on that mismatch.
- Provision the governed-agent scaffold with an approved behavior manifest and explicit read-only model-call permissions matching its gateway request.
- Stop the gateway from consuming run budget and forwarding to the upstream once `record()` flips an allowed decision to DENY (quota recheck, S6-VOLUME anomaly quarantine); the denial is now returned immediately instead of a 200 response.
- Treat a caller-supplied classification header as a floor instead of a bypass: the gateway and MCP proxy now always run the classifier, so the header can raise the effective label but can no longer suppress redaction or the egress ceiling.

### Added

- Agent identity manifests, additive SQLite migration, deployment approval and review expiry gates.
- Explicit tool verbs and autonomy requirements, use-case risk caps and mandatory L4 approval.
- Evidence-gated autonomy promotion, automatic drift step-down with owner and Knowledge Lead alerts, and `kognita agent deploy --manifest`.

## [0.4.1] - 2026-10-18

### Fixed

## [0.4.0] - 2026-10-18

### Added

- Circuit breaker and revocation (roadmap 0.4 item 14). `kognita.breaker` and `kognita.revocation`. A registered threshold on a use case, model version, prompt version, or policy version inserts a `CIRCUIT_BREAKER` policy when the counted flags in its window reach it, escalates to the accountable owner, and records an incident. Nothing trips until a threshold is registered, and there is no built-in default. A count at or above that threshold trips it. The trip is an incident of impact 1. Flags are confirmed-problem review flags, recorded outcomes, recorded near misses, and denials that are not themselves a breaker, a revocation, or a kill switch. The breaker is applied on the next decision even when a pack's `engages` would skip it. Reset closes that policy and requires the accountable owner and a citation. `kognita evidence affected --model | --policy | --usecase --from --to` lists clients who received model output or released tool output in the window, with each interaction. A denial is not receipt. `kognita revoke` stops one of `--agent`, `--model`, `--provider`, `--tool`, `--source`, `--client`, `--usecase`, or `--action`. The agent dimension engages the existing kill switch. `set_kill_switch(False)` is refused, and cites the revocation, while that agent revocation is open. `--provider` can be limited to `--limit-usecase` and an exclusive `--below` classification. `kognita reinstate` closes a revocation when an accountable owner cites the rule. Reinstating a provider needs every accountable owner of every use case that lists it; one owner records `REINSTATE_PENDING` and leaves the revocation in force. A revoked dimension denies until that reinstatement. A high-materiality use case records a kill-switch drill (`kognita drill run`) naming who activated it, how long until the next decision was denied, and how the fallback was reached. `kognita drill due` sets the next date. A drill past its due date denies a pilot or live high-materiality use case, and one with no drill scheduled is already overdue when the decision is given the register. The interval after a completed drill is `DRILL_DAYS` (90). The gateway records `attributes["provider"]` on each decision.
- Starter packs and the private-banking pack (roadmap 0.4 item 5). The five templates are `role-based-access`, `geo-fencing`, `data-classification`, `time-gated-access`, and `two-signature-approval-chains`. `private-banking` adds booking centre, RM location, client domicile, cross-border solicitation, research distribution, eligibility, suitability, mandate, concentration, relationship-manager principal equality, contact frequency, KYC and suitability-report human approval, and client communication. Each pack is policy files plus scenarios and passes `kognita policy validate --strict`. `PRINCIPAL_EQUALITY` requires the principal to equal one named attribute. `kognita packs list`, `show`, `load`, `update`, and `diff` look packs up by directory name. A user directory shadows a built-in pack of the same name, and `--overlay` merges policy files onto a pack; the same rule id is the user's. `kognita packs update` fetches from `https://github.com/mze3e/kognita` and installs only when a local `sha256:` pin or an `hmac:` signature matches. A bad pin, a bad signature, a missing pin, or a source that cannot be reached keeps the installed pack and appends `POLICY_CHANGE` with action `PACK_UPDATE_REFUSED`. A pack load appends `POLICY_CHANGE` with `source_hash` when stored rows change. `kognita serve --pack` loads that pack into the AI gateway. A pack does not skip a tripped `CIRCUIT_BREAKER` or an open revocation. Deciding does not fetch.
- Use-case register core (`kognita.usecases`). A decision given a register must name a registered use case, and a passing check cites that use case's accountable owner. This replaces the free-text purpose list for that call. The purpose list remains when no register is supplied. An agent cannot hold an owner role or an accountability seat. A tier 2 or higher use case with no Knowledge Lead is denied. Tier minimum controls are enforced at validation, activation, and decision. A tier 3 or 4 use case cannot be signed off or activated by one of its builders. Risk appetite and residual materiality are checked at registration and again at activation. A materiality rating the designated control function has not approved cannot be activated, and the control function cannot approve a use case it owns. A use case past its review date is denied, and activation after that date waits until the designated control function approves the materiality rating again. Tier floors and review periods are constants in `kognita.usecases`. A change of purpose or category clears activation. A pilot denies callers outside its user list and calls after its end date. Registry changes, including appetite changes, are `POLICY_CHANGE` evidence events. `kognita usecase list`, `show`, and `validate` read the register.
- Use-case register completion. An approved model is a model card (`provider/model@version`: intended use, known limitations, evaluation results, approver, approval date). A use case cannot name a model that has no card. A model call links the card id and content hash on its `MODEL_CALL` evidence. The gateway does not return a served model version that does not match an approved card. The stored decision is left as recorded, and a later `DENY` outcome event, linked to that decision and citing the model-card rule, records that the body was withheld. An unmediated entry records an assurance gap and a compensating control; a decision that cites it is a denial. A use case names the AI endpoints it uses on `ai_endpoints`. The gateway sets `x-kognita-unregistered-ai-endpoint` when the upstream is an endpoint no non-retired use case names. The flag does not change the decision. Appetite may set thresholds for AI incident count, AI incident impact, material use cases on one model provider, and material use cases breaching a registered primary-metric target. Material means residual materiality high or critical, or tier 3 or 4. A live use case with a primary metric and no measurement counts as a performance breach and is reported as unmeasured; a pilot does not. An incident that names no use case counts in every filtered report. `senior_management_report` lists material use cases and those measures, and, when written with evidence, records one `APPETITE_BREACH` per accountable owner of each breached measure. Retiring a use case engages the kill switch of every agent registered only to it, writes its retention period and erases content already past that period, and notifies the owners of use cases that depend on it. A later decision on a dependent is a denial while that dependency stays retired. A decision with no register still uses the purpose list. That check cites the agent's accountable owner, or the principal when the call names no agent. No owner fails closed.
- Policy language. `kognita policy load` parses a YAML policy file, type-checks it, and compiles it to policy rows. A plain load refuses an uncited rule. `kognita policy diff` prints a change as `## ADDED`, `## MODIFIED` and `## REMOVED` rules. `kognita policy validate --strict` fails on an uncited rule, a rule with no colocated scenario, a dangling reference, and an unresolved `[NEEDS CLARIFICATION: ...]` marker. An untested rule fails only that strict check and a change load. `kognita policy explain --envelope` reports which rules engage and the citation of each check. `kognita policy test` runs the scenarios beside the policy files. Loading a change file merges that delta into the current policy set, archives the change with the date, and compiles the result. A load that changes stored rows appends a `POLICY_CHANGE` evidence event recording the rule ids added, modified and removed, and the source file hash. `python -m kognita` starts the same command line as the `kognita` script.
- Structured document ingestion in `kognita.ingest`. `ingest` parses markdown, HTML or DOCX through Docling into one knowledge item per section. Each item stores a section locator (document reference, page, section path, a document-global character range, the parser's block span and bounding box) and the rule that classified that section. A nested section cannot be classified below its parent, and a preamble's classification is a floor for every later section. An explicit public marking does not lower a section below C1. Retrieval returns the passage that matched, and the retrieval evidence records the locator. The chunker is Kognita's. The `[docling]` extra pins `docling-slim[format-docx,format-html,format-markdown]==2.140.0`. It does not install `format-pdf`, Docling's chunking extra, or the `docling` metapackage. Core imports do not load Docling. PDF is refused until section headings can be read without torch.
- Framework adapters for Hermes Agent, the OpenAI Agents SDK, LangGraph and Pydantic AI. Each one is its own extra — `hermes-agent`, `openai-agents`, `langgraph`, `pydantic-ai` — and stays under 200 lines. Tool calls go through `run_governed` and model calls go through `Gateway.handle`, so a refusal cites the rule that decided it and does not call the tool or the provider. The core does not import any of the four frameworks; an import-linter contract says so. The adapters' tests run with no framework installed. A second test for each extra runs when that extra is installed. `hermes-agent` cannot be installed beside `openai`, `openai-agents`, `langgraph`, `pydantic-ai` or `docling`.
- Outcome metrics, near misses, and the review queue (roadmap 0.4 items 7, 13 and 15, for the measures that read the interaction record). `kognita.outcomes` computes cycle time, decision quality and reliability from interactions, runs and final decisions. Cycle time is mean seconds from open to the latest final decision, with RM effort reported beside it. Decision quality is the share of decided interactions with no edit, no rejection, no escalation and no outcome event. Reliability is the share of attached runs that finished with a policy allow or a final decision of allow, approve or modify, and without a denial, a failing budget check, a recorded exception, a recorded human recovery, or an open continuation. Each definition is version `METRIC_DEFINITION_VERSION`. A published snapshot is an `OUTCOME` event with action `METRIC`. `metric_trend` does not average two definition versions. A named primary metric with no measurement is a breach. `record_outcome` refuses a complaint, and every other outcome kind, unless the interaction has exactly one model-response hash, a model version and a final-decision approver. The link is that hash. Blocked actions and RM rejections are counted from decisions. Recording those near-miss kinds again is refused. Verifier blocks, unsafe drafts and unusual agent behaviour are recorded. `define_risk_criteria` stores an effective-dated criteria version. `screen_interaction` and `screen_response` score a response and queue a high-risk interaction, or a low-risk one chosen by a deterministic sample of the use case's sampling rate. A missing criteria row, a missing classifier, or an omitted vulnerability answer is high risk. `coverage_report` gives, per use case and risk tier, the share of interactions with a model response that were screened, queued and reviewed, and the mean time to review. An empty denominator is unmeasured. `record_review_finding` records `confirmed problem` or `cleared` without rewriting the screen. A confirmed problem appends a `REVIEW` event with action `REVIEW_FLAG`. Crossing a registered circuit-breaker threshold inserts the prohibiting policy. The finding does not rewrite the screen. `review_blocks_delivery` returns a citation while a before-delivery review is still queued or a confirmed problem stands. `kognita usecase metrics` and `kognita usecase coverage` print the reports. Once an interaction exists for a use case, the appetite performance measure uses the computed primary metric. With no interaction it still uses the latest self-reported `PRIMARY_METRIC`. A pilot with no measurement stays out of that appetite count.
- Flight recorder (roadmap 0.4 item 7). `kognita recorder` reads runs, decisions, citations, alerts, and effectiveness rates from the evidence chain. `runs` filters by actor, tool, and outcome. `show` drills into one run. `export` writes that run as self-verifying JSON: the chain from the start, with the run marked, checked by the same verifier as the store. A run the chain does not name is refused. Alerts are budget exceeded, repeated denials from one actor (`REPEATED_DENIALS`), a chain break, and classifier confidence drift (`CONFIDENCE_DRIFT_MIN_SAMPLE`, `CONFIDENCE_DRIFT_DROP`, one series per classifier model and version). Effectiveness rates are RM acceptance, edit, rejection, and wrong-client targeting, per use case, definition version `EFFECTIVENESS_DEFINITION_VERSION`. A rate with no denominator is unmeasured. Injection attempts and entitlement blocks stay unmeasured until an evidence event records them. A decision export carries both signals as unmeasured in that case, and carries a count only when the event records the attempt or the block. OpenTelemetry is the `[otel]` extra (`opentelemetry-api`, `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http`). `kognita serve --otel` attaches it only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. The engine does not import it. An export failure is written to stderr, kept on `EvidenceWriter.telemetry_failures`, and, on the gateway, set on `x-kognita-telemetry-export`. The decision event is unchanged. A decision now names `run_id` once the run row exists, so the recorder can find it.
- Governed client communication (roadmap 0.4 item 12), live-run intervention, and complaints. A client send is a `CLIENT_COMMUNICATION` event. It carries a communication level and a content provenance label, and it links the channel, the recipient reference, the content hash, and the final decision. A send with no final decision is a denial. An unregistered channel is a denial. Personal WhatsApp, Telegram, and personal email cannot be registered. Content rules are `CONTENT_POLICY` and `AI_DISCLOSURE`. House view and above needs a research attribution. Investment discussion and above needs a cross-border rule and a use case whose tier can be read. Product recommendation and above needs a suitability pass, an RM approval, and investment-risk language. A transaction is sent only when the content is the approved text. Tier 3 and above, from investment discussion upward, does not accept a plain allow. Tier 4, from product recommendation upward, needs a confirmer. AI provenance needs a disclosure rule to have decided whether the client must be told. A public send is denied when a client is named, and when the run it names has touched client data: the run is on a client interaction, or evidence on the run is classification C2 or above. A run id that is not recorded is a denial. A transaction after modify stays a denial until the approved full text is retained separately from the diff. Do-not-contact still denies the send. `pause_run`, `override_run`, `restrict_run`, and `recover_run` act on a live run attached to an interaction and append an `INTERVENTION` event. They do not rewrite a stored decision. A paused, recovered, or revoked run is denied on the next governed call. A deny override denies the next call. An allow override is recorded and does not outrank a later policy denial. Restrict adds tools to a denylist and can only lower the classification ceiling. Recover records compensating actions registered for the run, latest first, and stops the run. A complaint is recorded by `record_complaint`, which delegates to `kognita.outcomes.record_outcome` with kind `client complaint`. That is the one `OUTCOME` event and the one complaint payload. A client send calls `review_blocks_delivery` before it is sent. A before-delivery review that is still queued, or a confirmed problem on that timing, is a denial. An after-delivery item does not hold the send. `reconstruct` answers "What was communicated to the client?" from client sends.
- Interaction record, origination, and RM review (roadmap 0.4 items 9 to 11). One `interaction_id` spans the journey; runs and correlation ids attach to it, and `reconstruct` reads that span. Origination records why a client or product was selected as structured facts with citations. A bare score is refused. "Do not contact" is an outcome with a closed set of reasons. While it stands for a client, a later recommendation, an RM approve or modify, and any tool call a `CONTACT_FREQUENCY` policy lists under `tools` are refused. Other tool calls are unaffected. `reverse_do_not_contact` lifts the bar only when an authorised human records a cited reversal. A `CONTACT_FREQUENCY` policy that a recommendation would cross is recorded as do-not-contact and cites that policy. RM review stores a hash of the recommendation as rendered, a structured diff, and a content provenance label. AI-generated content that an RM edits stays `AI then human-edited`. Approve and modify require a complete approval packet and a human boundary defined beforehand. A two-signature gate records `FINAL_DECISION` only after `confirm_review`. `FINAL_DECISION` is also recorded for an allow or a deny when `run_governed` or `ask` is given an `interaction_id`. Approvals faster than the boundary's threshold, or an approver at or above a 99.9 percent approval rate over at least `RUBBER_STAMP_MIN_DECISIONS` (10) RM reviews, are flagged on that decision to the accountable owner named on the use-case register. Client communication is answered when a client send is on the interaction. A journey with no send still marks that question "not recorded".

### Fixed

- Resume, evidence head and affected clients (cross-review round 3). A held call records the identity of the pack that decided it (name, class, version and rule types). When `continue_run` re-checks a policy that came into force during the hold, it uses that pack's rules, `engages` scope and freshly loaded subjects, so a prohibition scoped to an unrelated dataset is skipped and a pack's own rule type is evaluated rather than reported as unevaluable. A pack is found again once `run_governed` or `ask` has used it in the running process. When it cannot be found, no longer matches, or fails while loading subjects, every policy that came into force during the hold escalates with a `PACK_CONTEXT` check whose citation gives the reason, and the call is not released. A continuation written before this change records no pack and is treated the same way. The `evidence_head` checkpoint only moves strictly forward: after the last event is removed, an append that would reuse its sequence is refused, and a store created with the earlier trigger is upgraded by `create_all`. `kognita evidence affected` no longer lists a model response the gateway withheld after recording it. The evidence tamper hook is no longer part of the public API; it lives in the test helpers, and the governed-agent demo rewrites a payload directly.
- Use-case register, resume and circuit breaker (cross-review round 2). Execution paths (`run_governed`, `ask`, the MCP proxy and the AI gateway) always decide against the use-case register. An empty register denies with `USE_CASE_REGISTERED` and does not fall back to the purpose list. `decide` without a register still uses that list, as do replay and policy scenarios. A held call re-evaluates policies that were not in force at the checkpoint before it is released. A denial, an escalation, or a human-approval requirement this grant does not satisfy withholds the action. The stored decision is kept, and the `RESUMED` event lists the new checks. Circuit-breaker evaluation windows flags by when they were recorded, then loads the decisions those flags cite by correlation id, including a decision older than the window. `--purposes` and a pack's purpose list constrain the purpose header. They do not authorize the call.
- Ingestion, budgets, affected clients and the roadmap (cross-review round 1). A passage whose parsed text differs from the raw source only by decoded HTML entities (`&amp;` is `&`), Markdown backslash escapes, or folded whitespace is located in a decoded view of the source and mapped back to exact source offsets, so `Tom &amp; Jerry` in HTML or Markdown ingests with a correct character range. A passage the source does not contain is still refused. A gateway bound to a run refuses a `run_id` header that names another run (`403`, "run is not bound to this client") and does not call the provider. `kognita evidence affected` lists released output that has no interaction, such as a gateway or MCP call, under `unlinked` as "client unknown" instead of leaving it out; a `--usecase` query matches it on the decision's purpose. The roadmap status line says v0.3.0 is the latest release and 0.4 is implemented on main and unreleased, and a short section records that 0.1 and 0.2 are tracked only in the changelog.
- Identity, authority and revocation on every path (cross-review round 1). The AI gateway and the MCP proxy take the principal from the bound client configuration. A `principal` header that names anybody else is a denial (`AGENT_IDENTITY`) and is not forwarded. A `purpose` header may pick a purpose the deployment configured (`--purposes`, or the client's own purpose); any other purpose header is a denial. Once a store has registered any use case, the register governs `run_governed`, `ask`, the MCP proxy and the gateway, including when nothing is in force at that instant; a store that never registered one keeps the purpose list. A single-signature grant in `continue_run` or `grant` must name the approver, cannot use the unassigned queue placeholder, and cannot be the requester. A held call re-reads the agent registry and kill switch, the register, open revocations, overdue drills and circuit breakers before it is released; a gate that closed while it waited withholds the call, the stored decision is kept, and the `RESUMED` event lists the checks that withheld it. The gateway re-checks open revocations and circuit breakers against the provider, model and version the provider actually served, and withholds the body with a `DENY` outcome linked to the stored decision on a match. Retrieval excludes items whose document reference, source label or id is under an open `source` revocation before scoring, whether or not the request named it.
- Evidence integrity, replay and retention (cross-review round 1). On SQLite, `create_all` installs triggers that refuse an UPDATE or DELETE on evidence rows, and an `evidence_head` checkpoint that records the last sequence and hash on every insert, only moves strictly forward, and cannot be deleted. A store created earlier gains both, and the checkpoint is backfilled from its last event. `verify_chain` and `reconstruct` compare the chain's tail with the checkpoint, so events removed from the end are reported. Replay with an envelope uses each agent's kill-switch state as the chain recorded it at the decision, not the current registry, and raises `ReplayMismatch` when the replayed outcome or envelope hash differs from the recorded one. Retained content that several use cases store is held per use case: each store adds or extends that use case's reference, and retention erases the body only when every reference has passed its use case's period.
- A gateway decision loads the policy rows, revocations, kill-switch drill dues, use cases, model cards, and risk appetite that are in force at that instant. Closed history stays in the tables and is not read. Those windows are indexed. The register loaded for the decision is the one the model-card link and the unregistered-endpoint flag use, so the call does not read it again. Circuit-breaker evaluation reads evidence inside the widest open threshold window, on an index of `recorded_at`, and does not walk the whole chain. The predecessor read on the evidence chain was already the latest sequence. Overhead was flat in evidence rows (p95 about 10 ms at 0, 1,000, and 10,000 rows) and grew with closed history: 1,000 closed rows of policies, revocations, drill dues, and use cases pushed p95 to about 80 ms, and 10,000 closed use-case versions to about 430 ms. After the bound read, 10,000 closed rows of each of those tables stays near an empty store (p95 about 9 ms). The 50 ms and 25 ms caps are unchanged. A sample that misses them is measured once more, and a failure reports both samples. The filled-store test keeps 10,000 evidence rows and 2,000 closed rows of each of those tables under the same caps.
- `mark` and `confirm` are exported from `kognita`. `continue_run` confirms a two-signature approval that is already marked. The confirming party is the `confirmer` argument when it is passed, and `approver_name` when `confirmer` is omitted. A blank confirmer is a missing signature. The confirming party must differ from the marker and the requester. A missing or duplicate signature does not confirm the approval and does not resume the run. A true resolution while that approval is still pending does not grant it and does not resume the run. A single-signature hold is unchanged: `continue_run` still grants it.
- The wheel build no longer adds the built-in packs twice. They ship once, at `kognita/packs/data`, as part of the package.
### Removed

- The Graphiti + Kuzu graph engine: `kognita.graph`, the `[graph]` extra, and the `[anthropic]`, `[groq]` and `[gemini]` extras, which installed only Graphiti. The Streamlit graph demo under `examples/` is removed with it. Kognita holds policies, guidelines and governance records only (ADR 0008). Touching a removed name such as `kognita.Kognita` or `kognita.GraphEngine` raises an `AttributeError` that names ADR 0008; anyone who still needs the engine can pin `kognita[graph]==0.3.0`. `kognita doctor` no longer lists graph, Anthropic, Groq or Gemini packages. `graphiti_core` and `kuzu` stay on the core's forbidden-import list.

### Changed

- The gateway overhead benchmark no longer treats the slowest call as the gate. Five warm-up calls are dropped, then 100 calls are measured. The 95th percentile must stay under 50 ms and the mean under 25 ms. The maximum is printed. One stalled call on a shared runner is not the measure. The gateway path is unchanged.
- The `openai` extra no longer caps the SDK below version 2. The cap existed for Graphiti. Kognita does not import the SDK (the embedder adapter uses `urllib`); the extra is for agents that call the AI gateway with it. openai 3.28 was checked through `kognita serve`: the provider received the redacted prompt, the client received the restored values, and a call with no agent name was denied without reaching the provider.

- The roadmap adopts the twelve gaps that mapping found. 0.4's use-case register gains a designated control function, complexity as a sixth materiality axis, inherent and residual materiality, quantitative risk-appetite measures, a single-provider dependency count, shared inventory identifiers, unmediated AI entries, pilot status and complete retirement; 0.4 revocation gains `--provider` and kill-switch drills; 0.6 fairness reporting covers proxy attributes. No release dates changed.
- `docs/control-frameworks.md` maps the trust architecture in Satya Nadella's post of 10 October 2026 (authority kept outside the model, models treated as insider risks, and seven observability principles) principle by principle. ## [0.3.0] - 2026-10-06

### Added

- Gateway overhead on `kognita serve`. The benchmark times an allowed `POST /v1/chat/completions` through the gateway built by `kognita serve --provider openai-compatible --upstream https://api.openai.com`, with `--purpose COLLABORATION`, `--purposes COLLABORATION`, `--agent dossier-agent`, and principal `alice`. The prompt is `Email ana@example.org about the notes`. `_urllib_transport` forwards the call to a local stand-in that returns a fixed completion, so the provider is not called. Overhead for a call is its wall time minus time inside `PatternClassifier.classify` and `PatternClassifier.calibrated_confidence` (the prompt and the response) minus time inside the stand-in. The decision path is the one already on main. The test fails when a call's overhead is not under 50 ms. On Linux 6.12.94+ x86_64, 4 CPUs, Intel(R) Xeon(R) Processor, MemTotal 16398384 kB, a sample of 30 sequential calls, none dropped, measured a maximum overhead of 37.010 ms and a mean of 9.469 ms. Classifier inference on that run averaged 0.041 ms per call, and the stand-in averaged 0.001 ms per call.

- Gateway failure mode, per use case. A use case is the purpose string already recorded as `use_case`. The default is `FAIL_CLOSED`: if the evidence store cannot record the call, the gateway refuses it and does not call the provider. `DEGRADED` may proceed only for a local model and content below classification C2 (C2 is client-identifying), and writes the decision and the model evidence once the store accepts writes again. A call is never forwarded without a decision. `kognita serve --failure-mode` sets the mode for `--purpose`.

- Reconstruction report: `kognita evidence reconstruct <interaction_id>` answers the ten reconstruction-test questions from the evidence chain and the retention store. The same command writes JSON and a readable document. It checks the chain and every pinned hash while building the report; a mismatch is a finding and the rest of the report is still written. Questions that belong to origination, RM review capture, and governed client communication are present and marked "not recorded". The report does not re-run the classifier, the model, or a tool.

- Pinned evidence for replay. Every policy check records the hash of the policy row as evaluated, and replay fails if that row's content no longer matches. An in-place edit of an effective policy is refused; a change is a new effective-dated row via `supersede_policy`. `RETRIEVAL` records a content hash and embedding model for each returned item. `MODEL_CALL` records the provider, the model name and version reported by the provider, the prompt template version, and hashes of the prompt as sent and the response as received. `TOOL_CALL` and `EGRESS` record a hash of the tool response. Prompts, responses, and source snapshots live in a content-addressed retention store keyed by those hashes, with a retention period per use case. Erasure deletes the bytes and appends an `ERASURE` event; the chain keeps the hash and still verifies.

- Flagship demo: `kognita scaffold --template governed-agent` creates a small app and a SQLite policy and evidence store. `run_demo.py` runs four scenarios: an allowed read with evidence, a denial with citations and no retrieval, redaction of `ana@example.org` through the AI gateway into a local stand-in (evidence stores the manifest hash, not the prompt), and an edited evidence row that `kognita evidence verify` reports as a break.

- MCP proxy: `kognita serve --mcp --root-config <config>`. The config names the backend MCP servers, the policy pack, the evidence database, and the default actor context. Every MCP call becomes an envelope and is authorised with `run_governed()`. The backend is contacted only when that call is released: an allow, or a human approval that already has a live grant. A denial, an escalation, and an ungranted human approval return the outcome and the citations and do not call the backend. A released call returns the proxied result. `POLICY_DECISION` evidence stores a hash and size of the tool arguments, not the arguments. Free-text tool arguments are classified only when a typed classification is missing; the classifier does not decide. A call with no agent name is denied. An agent name is accepted only when the bound client configuration lists it. An approved system trigger is a system actor. If the evidence store cannot record the call, the proxy refuses it and does not forward.

- AI gateway: `kognita serve --provider openai-compatible --upstream <url>`. Agents point `base_url` at the local gateway. The proxy speaks the OpenAI-compatible wire format, decides before any byte is forwarded, redacts through the egress guard, restores redacted spans, and classifies the response. `MODEL_CALL` and `EGRESS` evidence record hashes and references, not content. Token totals and cost reported by the provider count against the Run budget. A call with no agent name is denied, and an agent name is accepted only when the bound client configuration lists it. An approved system trigger is admitted and is not treated as a human. If the evidence store cannot record the call, the gateway refuses it.

- Classifier-derived envelopes at the decision boundary. `ask` classifies the question, and `run_governed` classifies free-text arguments, using the pattern classifier already in core. Typed attributes stay authoritative. Identity, purpose and subject references are not taken from the text. The recorded model, version, label, calibrated confidence and input hash are what `decide()` replays, so replay does not run the classifier. Below a `CLASSIFIER_CONFIDENCE` policy threshold the outcome is ESCALATE, never ALLOW. A citation that acted on a classifier label names both the policy rule and that label.

- `Run` budgets on `run_governed` and `ask`: call count, wall clock, classification ceiling, and cost when the caller already knows it. Token spend is recorded when the call site supplies it. Exceeding a budget is a DENY that cites that budget, and the consumption is written to the evidence chain.
- Durable suspend and resume for `HUMAN_APPROVAL`. A hold checkpoints at the policy decision and stores a content-hash continuation; `continue_run(run_id, approvals_resolved={approval_id: True/False})` resumes it. Evidence records the decision requested, then approved or rejected, then resumed.

### Fixed

- The 0.3 rollup "All Tier 0 defects closed" is ticked. Each box under "Tier 0 Defect Closure" was already ticked, and each claim still matches this commit. `HUMAN_APPROVAL` withholds the tool and the retrieval until a live grant. `continue_run` closes the approval loop. An empty or missing zone list is not visible. `SqliteVecIndex.search` returns the candidate stored with the embedding. Classifiers run at the decision boundary, and a typed classification still wins. `DomainPack.engages` is on the protocol. Evidence references are foreign keys. A missing or empty purpose list fails closed. Through the AI gateway and the MCP proxy, a call with no agent name is a denial, a registered agent and an approved system trigger are not, and an agent name outside the bound client configuration is a denial. The decision path was not changed.

- The conformance kit already passes. `TestDemoPackConformance` runs every `ConformanceCase` against the demo fixture pack in the normal test suite: fail-closed outcome precedence, a pure and deterministic `decide`, a citation on every check, a denial that names its basis, an unregistered agent denied, recorded decisions and refusals, an intact evidence chain, and a human approval bound to the envelope hash. None of those cases is skipped or expected-fail. The decision path was not changed.

- Text that relabels itself cannot widen permission. A classification written into the text, including every value from `C0` to `C3`, is not applied as a typed classification. The pattern classifier's hint may raise a classification and may not lower it, and `decide` on that label is not more permissive than the unhinted label under the same policy. A typed classification still replaces the label, including a lower one. The decision path was not changed.

- `DomainPack.engages` is already on the protocol, and the gap note that it is missing is stale. `run_governed`, `ask`, and the test harness pass the pack's `engages` into `decide`. A policy the pack does not engage is skipped. A policy it engages is evaluated. A pack that omits the method fails `isinstance(pack, DomainPack)`. The call sites still use `getattr`, so a pack that never meets that check still evaluates every effective policy. The decision path was not changed.

- Entitlement filtering already fails closed, and the gap note that describes an empty `zones` list as visible in every zone is stale. A missing or empty zone list is not visible in any zone. A caller with no zone does not match a listed zone. A classification or ceiling the filter cannot evaluate does not return the item. A zone the item lists, at or below the ceiling, is still returned, including the ceiling `retrieve` already grants when none is passed. The decision path is unchanged.

- Evidence payload references are foreign keys, enforced on the SQLite connection `make_engine` opens. `approval_id`, `policy_id`, `successor_id`, `run_id`, and `continuation_hash` are columns on `evidence_events`. Each `checks[].policy_id` is a row in `evidence_checks`, and each `items[].id` / `returned_ids` entry is a row in `evidence_items`. A dangling id is rejected. `runs.continuation_hash` references `continuations`. Content hashes stay in the payload: erasure deletes the bytes and the chain keeps the hash. `approvals.decision_id` and `entity_edges.from_entity_id` / `to_entity_id` already enforced; they are unchanged.

- `index_item` and `reindex` maintain `knowledge_vec` when given a `SqliteVecIndex`. Replacing an embedding deletes that item's previous vec row before the new one is inserted. `search` only reads. A hit is the candidate whose id was stored on the row, so two items that share embedding bytes stay distinct, and the vec `rowid` is not `item.id`. The score is `1 - distance`. A KNN with no rows, or only neighbours outside the candidate set, returns `[]`. `retrieve` still ranks that empty vector result lexically.

- The purpose check fails closed when the purpose list is missing or empty. A configured list still allows a listed purpose and denies an unlisted one. `kognita serve` takes a repeatable `--purposes` allowlist for the AI gateway, separate from `--purpose`. The MCP root config takes a `purposes` list, separate from `actor.purpose`. With neither list set, those processes deny the call.

- Degraded mode, while the evidence store is down, no longer lets a classification header keep a call below C2. The header is a floor. The classifier runs on the JSON values that would be forwarded after parsing, so client-identifying content outside the extracted prompt, including the OpenAI `user` field, is refused and the provider is not called. A unicode escape of that content cannot stay below C2.

- `HUMAN_APPROVAL` no longer retrieves or returns data from `ask`. A held tool call or retrieval runs only after the approval is actually granted; a denied approval does not execute.

## [0.2.0] - 2026-09-04

### Added

- **Decision engine core**: `decide()` function that determines whether an AI request is permitted before any data is retrieved
- `Envelope` dataclass for structured access requests (principal, purpose, tool, subject, etc.)
- Policy-based access control with multi-regime support (HK SFC, DIFC DFSA, etc.)
- Evidence recording: every decision is logged with its basis (which policy/regime allowed or denied it)
- `EvidenceWriter` and `EvidenceReader` for decision auditability
- Two-signature approvals (ADR 0006): separation of duties for high-risk actions
- Proposal-then-apply pattern (ADR 0007): propose changes, verify, then execute atomically
- Identity and authority model (ADR 0005) with role-based access control
- Tool arguments channel (ADR 0004): structured, hashable arguments for reproducibility
- Governance module with rule sets, regimes, and policy evaluation
- Retrieval integration: controlled access to knowledge graphs (optional `[graph]` extra)
- SoR (System of Record) mirror architecture for safe separation of concerns
- Import layering contracts via `import-linter` to prevent architectural drift
- CLI with `kognita` command and subcommands
- Comprehensive test suite (75+ tests) with governance conformance validation

### Changed

- Refactored from PDF→graph library to decision engine for AI governance
- Core now depends only on pydantic, sqlmodel, numpy, python-dotenv
- Graph, embeddings, and LLM features moved to optional extras: `[graph]`, `[vec]`, `[openai]`, etc.
